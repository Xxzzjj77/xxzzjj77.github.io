# Bugku CTF Web 入门：计算器题解 (Writeup)

## 前言
这是我网络安全学习旅程中的第二道 CTF 实战题目。题目名叫“计算器”，虽然界面看似是一个简单的数学加法验证，但背后其实隐藏了前端验证绕过的知识点。

**I'm here, ready for the Cybersecurity world**

## 一、 题目信息
- **平台**：Bugku CTF
- **题目类型**：Web
- **题目描述**：`33 + 94 = ?`
- **靶场链接**：`http://160.202.254.160:17200` （注：靶场地址具有时效性）

## 二、 解题过程
### 1. 信息收集
打开题目链接，页面非常简洁，只有一个加法算式 `33 + 94 = ?` 和一个输入框。
尝试输入计算结果 `127` 并点击“验证”，发现没有任何反应，或者提示错误。这说明前端可能做了限制，或者答案没有直接提交给服务器。

### 2. 查看网页源码
对于此类题目，最直接的方法就是查看前端源码。
- 在网页上按 **`Ctrl + U`**（或右键 -> 查看网页源代码）。
- 在源码中按 **`Ctrl + F`** 搜索 `flag` 关键字。

### 3. 寻找 Flag
在源码中，我们可以直接找到被注释掉的 Flag，或者可以发现一段 JavaScript 代码。
本题中，通过查看源码，成功找到了隐藏的 `flag{xxxxx}` 字符串。将其复制出来即可。

## 三、 总结与收获
本题考察的是 **前端验证绕过（Client-Side Validation Bypass）** 以及 **源码泄露** 漏洞。
- 许多网站开发者会在前端使用 JavaScript 或 HTML 属性（如 `maxlength`）来限制用户的输入。然而，这些限制完全在用户的浏览器端执行，攻击者可以通过禁用 JavaScript、修改 HTML 代码或直接抓包发送请求来绕过。
- **安全启示**：所有的安全校验都必须在服务端完成。前端验证仅为了提升用户体验，不能作为安全防护的手段。同时，切勿在源码中泄露敏感信息（如 Flag、密钥、注释等）。

这道题让我意识到，看似简单的界面背后，往往隐藏着可以通过“查看源码”发现的秘密。多动手、多观察，是网络安全学习的关键。
